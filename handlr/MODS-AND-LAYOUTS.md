# Layout and mod files

The rules are in [the shipped guide](../defaults/AGENTS.md), under Layouts and
“Layouts and mods other people made.” `RECIPE.md` and a real `preview.png` are
sharing artifacts, not files the app requires to load a mod. A layout's root
`preview` points to a separate Settings thumbnail, usually an SVG.

## Our sources

| Component | Recipe and screenshot | Runtime files |
| --- | --- | --- |
| Native panel workspace | `prototype/RECIPE.md`, `prototype/preview.png` | `prototype/layouts/panel-workspace-native.json`, matching SVG, `prototype/workspaces/panel-workspace-native.json` |
| Earlier fixed-layout demo | Covered by the workspace recipe; its own Settings SVG | `prototype/layouts/panel-workspace-prototype.json`, matching SVG, `prototype/mods/workspace-prototype/{main.js,actions.js,mod.json}` |
| Context | `mod-worktrees/context/{RECIPE.md,preview.png}` | Build/installer emits `main.js`, `mod.json`, `context.svg`, `native/`, `src/`; configured CLI, launcher and guide are also required |
| Toolbox | `mod-worktrees/toolbox/{RECIPE.md,preview.png}` | Build emits `dist/mods/toolbox/` and companion `toolbox-tabs/`, including JS, manifests, SVG and setup guide |
| Rigs | `mod-worktrees/rigs/{RECIPE.md,preview.png}` | `mods/rigs/{main.js,setup.js,mod.json,AGENTS.md}` plus installed Node/CLI checkout paths |
| Ticket | Separate `Herdr Ticket` repository: `RECIPE.md`, `preview.png` | `build/ticket/{main.js,mod.json,runtime.js}` plus the built CLI checkout |

Context, Toolbox and Rigs are independent Git repositories, ignored by this
repository. Their new recipes/screenshots must be committed in those repositories
to travel with those sources. Their pre-existing local edits remain intact.
The bundled Machines panel belongs to the host's `defaults/mods/machines/`;
it is not an independent gallery package and needs no separate gallery recipe.
Ticket is maintained in the separate sibling `Herdr Ticket` repository on its
`handlr-ui` branch; its implementation and sharing files were included in the
follow-up audit. Shipped default mods use the host guide/API contract.

`npm run build` regenerates the prototype layouts and native workspace document.
The macOS portable packager reads the native layout rather than defining a
second center layout in its own code. It filters to bundled panels and seeds
missing layout/document/Settings-preview files. Optional external mods are not
part of that portable package. The full source workspace document requires
those mods to be installed separately.

## Companion files and ownership

- Runtime minimum: `mods/<name>/main.js` with a default-exported `View` class.
  `mod.json` is optional to Herdr, but our panels carry it for discoverability
  and `workspace_header`. Include every relative JS import and referenced asset.
- Layout: `layouts/<name>.json` with valid node IDs, mod references and a working
  root preview path. A native workspace also needs the matching
  `workspaces/<name>.json`; this extension requires the Handlr fork.
- Sharing: one root `RECIPE.md` and actual `preview.png` per offered package,
  plus runtime layout/mod files. The six recipe sections describe real behavior,
  dependencies, external access, pitfalls and acceptance checks. Keep the
  Settings thumbnail distinct from the screenshot.
- `herdr.d.ts`, `gpui-kit.d.ts`, installed `AGENTS.md` and mod `jsconfig.json`
  are generated by the host. Use current installed declarations; do not create
  hand-maintained copies as missing runtime files. The older prototype has
  historical declaration/config snapshots; those are not a new API authority.
- `keys.json` is only needed when a package needs its own bindings. Preserve
  existing keys and ask before replacing a collision. These recipes add no keys.
- `themes/` and `fonts/` are optional. These panels use host theme colors and
  host fonts; no new font/theme package is required.
- `shared.json`, `data/`, `installed.json`, `seen.json`, window/view state,
  `layouts/.state/`, sockets, records, drafts and absolute local CLI configuration
  are runtime data. Do not distribute a developer's copies as package defaults.

The external preview images are crops of the 2026-11-13 shared-header capture;
their recipes identify empty/error states and date. The workspace preview is
the actual 2026-11-14 Handlr window. Neither establishes untested interactions.
For a public listing, capture clean representative content and review the
screenshots before publishing. Publishing/indexing uses GitHub topics
`herdr-mod` / `herdr-layout`; no repository topics or publishing were changed.

## Before calling a package ready

Build from source, inspect all runtime dependencies, run `herdr-app check` on
each changed mod, and inspect status plus a screenshot in a scratch app home
and isolated Core session. Eager checker success does not prove deferred rows,
async states or desktop interaction. An existing personal layout should never
be overwritten to test a bundle. A complete copy-only gallery export of the
native workspace remains separate work: it requires the fork and optional
external CLI-backed mods, not just a layout JSON file.

Audit verification (2026-11-14): the running Handlr status had no mod errors.
Recipes were added from source/README behavior, and screenshots inspected.
Generation and all 14 JavaScript tests passed. The prototype controls and the
installed Context, Toolbox and Rigs copies passed the native checker (outside
the macOS sandbox). Eight relative imports in those installed panels resolved.
Recipe sections and PNG signatures passed file checks; packaging passed a
JavaScript syntax check. No release package was built or installed, and no
lifecycle or desktop interaction acceptance was rerun. Historical screenshots
are not fresh lifecycle or desktop acceptance.
